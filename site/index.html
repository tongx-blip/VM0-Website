Granular permissions

Grant access one connector and one action at a time, per Agent. Reading a shared Drive folder and saving a Gmail draft are two separate grants, so the Agent that writes your weekly summary never quietly gains the ability to send it. Nothing is reachable because something else already had it.

Set up an Agent

Approval gates

Sensitive writes wait for an explicit approval instead of running on their own. The request names the connector, the action and how long the grant lasts, and it is a person who answers it — not a rule buried in a settings page six months ago. Deny once and the run carries on without that step.

Try an approval gate

Isolated execution

Each run gets its own microVM: a fresh machine with nothing left over from the last task and no route to another run’s files. When the work finishes the machine is destroyed, so there is no long-lived box sitting somewhere accumulating your data between jobs.

Run your first task

Credentials stay out of the run

Tokens are attached at the network layer on the way out, so the Agent never reads them and cannot copy one into a file, a log or a message. Calls to hosts you have not connected do not get a token — they do not leave the sandbox at all.

Connect a tool

Traceable by default

Every run keeps an activity trail: what was read, what was written, who approved it and when. You can replay any run after the fact instead of taking its word for it — and the engine underneath is open source, so the behaviour can be checked rather than believed.
